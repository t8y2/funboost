# Funboost 任务链路追踪实现方案

## 一、是否常见需求？

**非常常见**，尤其在以下场景：

1. **微服务架构**：一个请求可能触发多个队列任务，需要追踪完整调用链
2. **RPC 链式调用**：函数 A 调用函数 B，B 又调用 C，需要知道完整路径
3. **问题排查**：当某个任务失败时，需要知道是谁触发的、影响了谁
4. **性能分析**：分析整个调用链的耗时瓶颈

业界成熟方案如 **Jaeger**、**Zipkin**、**SkyWalking**、**阿里鹰眼** 都是做这个的。

## 二、实现方案

### 方案概览

```
┌─────────────────────────────────────────────────────────────┐
│                      链路追踪架构                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   Task A (root)                                             │
│   trace_id: abc123                                          │
│   task_id: task_001                                         │
│   parent_task_id: null                                      │
│        │                                                    │
│        ├──────────────┬──────────────┐                      │
│        ▼              ▼              ▼                      │
│   Task B          Task C          Task D                    │
│   trace_id: abc123  trace_id: abc123  trace_id: abc123      │
│   task_id: task_002  task_id: task_003  task_id: task_004   │
│   parent: task_001   parent: task_001   parent: task_001    │
│        │                                                    │
│        ▼                                                    │
│   Task E                                                    │
│   trace_id: abc123                                          │
│   task_id: task_005                                         │
│   parent: task_002                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 核心概念

| 字段 | 说明 |
|------|------|
| `trace_id` | 整条调用链的唯一标识，从根任务一直传递到最末端 |
| `task_id` | 当前任务的唯一标识（funboost 已有） |
| `parent_task_id` | 父任务的 task_id，用于构建调用树 |
| `span_id` | 可选，更细粒度的追踪（如函数内部多次调用） |
| `depth` | 调用深度，用于限制链路层级防止无限递归 |

## 三、实现步骤

### 第一步：数据模型扩展

在消息体和结果持久化中增加追踪字段：

```python
# 消息体扩展
{
    "task_id": "task_001",
    "trace_id": "trace_abc123",      # 新增：链路追踪ID
    "parent_task_id": "task_000",    # 新增：父任务ID
    "depth": 2,                       # 新增：调用深度
    # ... 原有字段
}
```

### 第二步：上下文传递机制

```python
# 方案：使用 contextvars 在函数执行期间传递追踪上下文
import contextvars

# 当前任务的追踪上下文
_trace_context = contextvars.ContextVar('trace_context', default=None)

class TraceContext:
    trace_id: str
    task_id: str
    depth: int
```

当消费者执行函数时：
1. 从消息中提取 `trace_id`、`parent_task_id`
2. 设置到 `contextvars` 中
3. 如果函数内部调用了其他 funboost 队列，自动注入追踪信息

### 第三步：自动注入机制

修改 `publisher.publish()` 方法：

```python
def publish(self, msg_body, task_id=None, ...):
    # 获取当前追踪上下文
    ctx = _trace_context.get()
    
    if ctx:
        # 子任务继承父任务的 trace_id
        trace_id = ctx.trace_id
        parent_task_id = ctx.task_id
        depth = ctx.depth + 1
    else:
        # 根任务，生成新的 trace_id
        trace_id = generate_trace_id()
        parent_task_id = None
        depth = 0
    
    # 注入到消息体
    full_msg = {
        **msg_body,
        '_trace_id': trace_id,
        '_parent_task_id': parent_task_id,
        '_depth': depth,
    }
```

### 第四步：存储扩展

MongoDB 结果表增加索引：

```python
# 索引设计
db.collection.create_index([('trace_id', 1)])
db.collection.create_index([('parent_task_id', 1)])
db.collection.create_index([('trace_id', 1), ('depth', 1)])
```

## 四、查询 API 设计

```python
# 1. 根据 trace_id 获取完整调用链
GET /funboost/trace/{trace_id}
# 返回: 该 trace 下所有任务，按 depth 和时间排序

# 2. 根据 task_id 获取所属调用链
GET /funboost/trace/by_task/{task_id}
# 返回: 先查出 trace_id，再返回完整调用链

# 3. 获取任务的子任务
GET /funboost/task/{task_id}/children
# 返回: parent_task_id = task_id 的所有任务
```

## 七、与现有代码的关联

### 现有 current_task 模块

Funboost 已有 `funboost/core/current_task.py`，提供了在函数执行期间获取当前任务信息的能力：

```python
from funboost import current_task

# 在被装饰的函数内部可以获取
task_id = current_task.task_id
queue_name = current_task.queue_name
```

链路追踪可以扩展此模块，增加：
- `current_task.trace_id`
- `current_task.parent_task_id`
- `current_task.depth`

### 现有结果持久化

`funboost/core/function_result_status_saver.py` 已经实现了任务状态和结果的 MongoDB 持久化。

链路追踪需要在保存时增加 `trace_id` 和 `parent_task_id` 字段。
