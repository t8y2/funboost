## 🔑 核心结论

### 性能对比

```
======================================================================
               Funboost vs Celery 性能对比 (Redis, 单线程模式)
======================================================================
Funboost: 500,000 条 | Celery: 20,000 条

--- Funboost SINGLE_THREAD ---
  发布: 500000 条 |     4.58秒 |   109201 msg/s
  消费: 500000 条 |     8.40秒 |    59488 msg/s

--- Celery solo ---
  发布: 20000 条 |     7.12秒 |     2810 msg/s
  消费: 20000 条 |    16.46秒 |     1215 msg/s

>>> 消费吞吐量倍数: Funboost 是 Celery 的 49.0 倍
>>> 发布吞吐量倍数: Funboost 是 Celery 的 38.9 倍
======================================================================
```

## 🎯 快速参考

### Broker 选择

```
需要 ACK？
├── 是 + Redis → REDIS_ACK_ABLE ⭐推荐
├── 是 + Redis 5.0+ → REDIS_STREAM
└── 否 + 追求速度 → REDIS

需要 Kafka → KAFKA_CONFLUENT ⭐推荐
需要 RabbitMQ → RABBITMQ_AMQPSTORM ⭐推荐
```

### 并发模式选择

```
I/O 密集型 → ASYNC (1000+ 并发)
CPU 密集型 → THREADING + mp_consume(8)
爬虫 → ASYNC + mp_consume(4)
顺序处理 → SINGLE_THREAD
```

### Mixin 选择

```
外部 API 调用 → CircuitBreakerConsumerMixin
批量写入 DB → MicroBatchConsumerMixin
监控 → PrometheusConsumerMixin
链路追踪 → AutoOtelConsumerMixin
额度限制 → PeriodicQuotaConsumerMixin
```
