
## 三、并发模式对比

### 3.1 并发模式总览

| 对比项 | Funboost | Celery |
|--------|----------|--------|
| **并发模式数量** | **5 种** | 4 种 |
| **多进程叠加** | ✅ 原生 | ⚠️ 互斥 |
| **线程数** | `concurrent_num` | `-c N` |
| **协程支持** | ✅ 完整 | ✅ 基础 |

### 3.2 Funboost 并发模式

```python
from funboost import boost, ConcurrentModeEnum, BoosterParams

# 模式1: 线程模式（兼容 async 函数）
@boost(BoosterParams(
    queue_name='thread_mode',
    concurrent_mode=ConcurrentModeEnum.THREADING,
    concurrent_num=50
))
def task1(x):
    pass

# 模式2: Asyncio 协程
@boost(BoosterParams(
    queue_name='async_mode',
    concurrent_mode=ConcurrentModeEnum.ASYNC,
    concurrent_num=100
))
async def async_task(x):
    await asyncio.sleep(0.1)

# 模式3: Gevent 协程
@boost(BoosterParams(
    queue_name='gevent_mode',
    concurrent_mode=ConcurrentModeEnum.GEVENT
))
def gevent_task(x):
    pass

# 模式4: Eventlet 协程
@boost(BoosterParams(
    queue_name='eventlet_mode',
    concurrent_mode=ConcurrentModeEnum.EVENTLET
))
def eventlet_task(x):
    pass

# 模式5: 单线程（不预取）
@boost(BoosterParams(
    queue_name='single_thread',
    concurrent_mode=ConcurrentModeEnum.SINGLE_THREAD
))
def solo_task(x):
    pass
```

### 3.3 多进程叠加

**Funboost 独有的多进程 + 多线程叠加：**

```python
# 8 进程 × 50 线程 = 400 并发！
@boost(BoosterParams(
    queue_name='high_throughput',
    concurrent_mode=ConcurrentModeEnum.THREADING,
    concurrent_num=50
))
def heavy_task(x):
    pass

# 启动 8 个进程，每个进程 50 线程
heavy_task.mp_consume(8)

# 或者组合
heavy_task.multi_process_start(8)  # 别名
```

**Celery 的限制：**

```bash
# Celery 无法叠加，只能选一种
celery -A app worker -P prefork -c 10    # 多进程
celery -A app worker -P eventlet -c 100  # 协程
# 不能同时用！
```

## 四、API 设计对比

### 4.1 装饰器风格

#### Funboost（零侵入）

```python
from funboost import boost, BoosterParams

@boost(BoosterParams(
    queue_name='my_queue',
    qps=10,
    max_retry_times=3
))
def process_order(order_id, amount):
    # 业务逻辑
    return f"订单 {order_id} 已处理"

# 三种调用方式
result = process_order(1001, 99.9)  # 直接调用（普通函数）
process_order.push(1001, 99.9)       # 异步任务
process_order.delay(1001, 99.9)      # delay 是 push 的别名
```

#### Celery（需继承）

```python
from celery import Celery, Task

app = Celery('tasks')
app.config_from_object('celeryconfig')

class ProcessOrderTask(Task):
    def run(self, order_id, amount):
        return f"订单 {order_id} 已处理"

process_order = app.register_task(ProcessOrderTask())

# 调用
process_order.delay(order_id=1001, amount=99.9)
```

**对比：**
| 维度 | Funboost | Celery |
|------|----------|--------|
| 代码行数 | 5 行 | 15+ 行 |
| 需继承 | ❌ | ✅ |
| 直接调用 | ✅ | ❌ |
| 类型提示 | ✅ Pydantic | ❌ |

### 4.2 发布任务

| 方法 | Funboost | Celery |
|------|----------|--------|
| **简单发布** | `func.push(args)` | `func.delay(args)` |
| **带控制参数** | `func.publish(msg, TaskOptions(...))` | `func.apply_async(countdown=...)` |
| **定时发布** | `func.aio_publish(msg, eta=...)` | `func.apply_async(eta=...)` |
| **延迟发布** | `func.publish(msg, countdown=5)` | `func.apply_async(countdown=5)` |
| **优先级** | `func.publish(msg, priority=10)` | `func.apply_async(priority=5)` |
| **异步发布** | `await func.aio_push(args)` | - |
| **批量发布** | `func.multi_process_pub_params_list(list)` | - |

### 4.3 启动消费

| 方法 | Funboost | Celery |
|------|----------|--------|
| **普通消费** | `func.consume()` | `celery worker -A app` |
| **多进程消费** | `func.mp_consume(n)` | `celery worker -c N` |
| **多队列消费** | `consume_queues('q1', 'q2')` | `celery worker -Q q1,q2` |
| **按分组启动** | `BoostersManager.consume_group('group')` | - |
| **启动全部** | `BoostersManager.consume_all()` | - |
| **Web 界面** | ✅ 内置 | ❌ 需 Flower |

### 5.1 重试机制

#### Funboost 重试

```python
@boost(BoosterParams(
    queue_name='retry_demo',
    max_retry_times=3,  # 最多重试 3 次
    # 指数退避重试
    is_using_advanced_retry=True,
    advanced_retry_config={
        'interval_start': 1,      # 初始间隔 1 秒
        'interval_max': 60,       # 最大间隔 60 秒
        'interval_step': 2,       # 每次翻倍
        'max_retries': 5
    }
))
def task_with_retry(x):
    if x < 0:
        raise Exception("负数不能处理")
    return x * 2
```

#### 手动触发重试

```python
from funboost import boost, ExceptionForRetry, BoosterParams, fct

@boost(BoosterParams(queue_name='manual_retry'))
def task(x):
    if some_condition:
        raise ExceptionForRetry("需要重试")
    return x
```

#### Celery 重试

```python
from celery import Task

class MyTask(Task):
    autoretry_for = (Exception,)
    retry_kwargs = {'max_retries': 3}
    retry_backoff = True
    retry_backoff_max = 600

    def run(self, x):
        if x < 0:
            raise self.retry(args=[x])
        return x * 2
```

```python
@boost(BoosterParams(
```

```python
@celery.task(bind=True)
def compute(self, x, y):

# 获取结果

app.conf.result_backend = 'redis://localhost/1'
```

```python
    broker_exclusive_config={
        'failure_threshold': 5,
        'recovery_timeout': 60
    }
))
def protected_task(x):
    pass

# 微批处理
@boost(BoosterParams(
    queue_name='batch',
    consumer_override_cls=MicroBatchConsumerMixin,
    broker_exclusive_config={
        'batch_size': 100,
        'batch_timeout_seconds': 1.0
    }
))
def batch_process(batch):
    # batch 是 100 条消息的列表
    pass
```

### 9.1 基准测试结果

```
======================================================================
               Funboost vs Celery 性能对比 (Redis, 单线程模式)
======================================================================
Funboost: 500,000 条 | Celery: 20,000 条

--- Funboost SINGLE_THREAD ---
  发布: 500000 条 |     4.58秒 |   109201 msg/s
  消费: 500000 条 |     8.40秒 |    59488 msg/s

--- Celery solo ---
  发布: 20000 条 |     7.12秒 |     2810 msg/s
  消费: 20000 条 |    16.46秒 |     1215 msg/s

>>> 消费吞吐量倍数: Funboost 是 Celery 的 49.0 倍
>>> 发布吞吐量倍数: Funboost 是 Celery 的 38.9 倍
======================================================================
```

### 9.2 性能差异原因分析

| 原因 | 说明 |
|------|------|
| **架构层级** | Funboost 直接操作 Redis，Celery 多层抽象 |
| **序列化** | Funboost JSON，Celery pickle + 签名 |
| **依赖链** | Funboost 极简，Celery → billiard → kombu |
| **企业负担** | Celery 需支持任务路由、监控、结果存储 |
| **设计哲学** | Funboost 专注任务调度，Celery 什么都管 |

## 附录：Broker 选型指南

### 快速选择

```
需要消费确认？ + Redis？
├── 是 → REDIS_ACK_ABLE 或 REDIS_STREAM
└── 否 → REDIS

需要优先级？
├── 无级优先级 → REDIS_ZSET_PRIORITY
└── 多级优先级 → REDIS_PRIORITY 或 RabbitMQ

需要延迟消息？
├── Redis → REDIS_ZSET_DELAY
└── RabbitMQ → 内置延迟插件

需要高性能？
├── 本地 → MEMORY_QUEUE
└── 分布式 → REDIS 或 RABBITMQ_AMQPSTORM
```
